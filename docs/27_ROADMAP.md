# Post-Hackathon Roadmap

Do not build these before the three-day MVP is complete.

## Phase 1 - community product

- follows and curated lists
- notifications
- group/community spaces built around public theses
- richer search
- verified branch outcome history
- mobile PWA polish

## Phase 2 - creator economics

- Perpl builder code attribution
- transparent platform fee
- optional creator share from routed activity after legal/product review
- community revenue splits

Core principle: reward value creation without turning every social action into a token incentive.

## Phase 3 - branch automation

- Branch Watch with strict user-defined policies
- stop/expiry/revoke
- risk caps
- audit log
- optional Privy delegated signer with constrained policy

This is closer to the Perpl automation bounty/product area and should be built only with mature safeguards.

## Phase 4 - portable reputation

- public reputation API
- signed attestations for Originality/Contribution/Influence
- community-specific score lenses
- third-party clients using the open thesis graph

## Phase 5 - market expansion

- additional Monad trading venues
- spot theses
- prediction/cultural markets only if they reinforce the social primitive

Do not make venue aggregation the company thesis. FORK's moat is the provenance/reputation graph around ideas.

## Long-term moat

The valuable dataset is not simply trades.

It is:

- who originated an idea
- how it was modified
- who chose which branch
- what was actually executed
- which contributors consistently improve others' ideas

That graph can become a portable reputation layer for collaborative financial research.
